1. The Project: SecureAI API

SecureAI API is a small Python FastAPI application that calls Azure OpenAI to answer questions. It is deliberately simple as an application — the complexity lives in the security controls you layer onto it. The goal is not to build a polished product; it is to give every Azure security control a concrete reason to exist.

At the end of the course, the project includes:

  • Azure App Service — compute, HTTPS-only, system-assigned managed identity
  • Azure Key Vault — secrets (API keys, connection strings), RBAC mode, private endpoint
  • Azure SQL Database — application data, TDE, firewall, Defender for SQL
  • Azure OpenAI — AI endpoint called by the app via managed identity
  • Azure Virtual Network — private subnet, NSGs, private endpoints to PaaS services
  • Defender for Cloud — CSPM, workload protection plans across all resources
  • Microsoft Sentinel — log ingestion, analytics rules, automated response

3. The Deploy-Test-Destroy Principle

This project has no persistent infrastructure. You deploy from Bicep, apply and verify the security controls for that track, then tear it all down. The Bicep code is the artefact — not the live Azure resources. This keeps costs near zero and teaches the real-world practice of infrastructure as code as the source of truth.

Estimated cost per session: A full Track 1 deploy (App Service B1 + Key Vault standard) running for 2–3 hours costs under $1. Always run deploy.ps1 -Destroy at the end of each session. Track 2+ adds SQL and VNet, which cost slightly more — still under $3/session if torn down promptly.

The workflow for every track capstone session:

  1. Pull the latest Bicep code from the project repo.
  2. Run .\deploy.ps1 — creates resource group and deploys all modules.
  3. Follow the verification steps in the track capstone guide.
  4. Apply any manual portal steps (e.g. PIM configuration, Conditional Access).
  5. Run .\deploy.ps1 -Destroy — deletes the resource group and all resources.
# Deploy
.\capstone\scripts\deploy.ps1

# Verify (track-specific)
.\capstone\scripts\verify-identity.ps1

# Destroy
.\capstone\scripts\deploy.ps1 -Destroy

4. IaC Repo Structure

The capstone Bicep code lives in a capstone/ folder within this workspace (or in its own git repo if you prefer). The structure grows as you add tracks: 

capstone/
  main.bicep              ← top-level orchestration; calls all modules
  params.json             ← environment-specific values (not committed if it contains IPs)
  modules/
    app-service.bicep     ← App Service plan + site, system-assigned MI  [Track 1]
    key-vault.bicep       ← Key Vault, RBAC mode, soft-delete, firewall  [Track 1]
    rbac.bicep            ← RBAC assignments (MI → KV Secrets User)      [Track 1]
    policy.bicep          ← Azure Policy assignment on RG                [Track 1]
    networking.bicep      ← VNet, subnets, NSGs, private endpoints        [Track 2]
    sql.bicep             ← Azure SQL, firewall, TDE, auditing            [Track 2]
    storage.bicep         ← Storage account, firewall, Defender           [Track 2]
    openai.bicep          ← Azure OpenAI endpoint, network rules          [Track 4]
    defender.bicep        ← Defender for Cloud plans                      [Track 5]
    sentinel.bicep        ← Sentinel workspace, data connectors           [Track 5]
  scripts/
    deploy.ps1            ← deploy-test-destroy wrapper
    verify-identity.ps1   ← Test MI can read Key Vault secret             [Track 1]
    verify-network.ps1    ← Test private endpoint connectivity            [Track 2]

6. Prerequisites

Before starting Track 1, confirm you have the following installed and configured:

  • Azure CLI — Install guide. Run az login and az account show to verify.
  • Bicep CLI — installed automatically with Azure CLI 2.20+. Verify with az bicep version.
  • Azure subscription — your $100/month subscription (not MS Learn sandbox — resources must persist for the session). Run az account set --subscription "<your-subscription-id>".
  • PowerShell 7+ — for the deploy/verify scripts. Verify with $PSVersionTable.
Cost guard: Set a budget alert in the Azure portal under Cost Management → Budgets. Set a $30/month alert threshold to catch any runaway resources before they consume your credits.
